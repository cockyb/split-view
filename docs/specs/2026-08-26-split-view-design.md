# Split View 브라우저 확장 제품·기술 설계

- 상태: 확정안
- 작성일: 2026-08-26
- 대상: Chromium 기반 브라우저(Chrome, Edge, Whale) 데스크톱
- 작업명: Split View

## 1. 목표

Split View는 치지직과 SOOP의 공개 라이브 방송을 플랫폼 웹 플레이어 없이 확장 프로그램 전용 창에서 재생하는 Chromium 확장이다. 사용자는 라이브 페이지에서 확장 버튼을 누르거나 방송 URL을 붙여넣어 최대 네 개의 방송을 한 창에 배치할 수 있다. 전용 창은 영상 자체를 최우선으로 보여주며, 조작 UI는 사용 중에만 나타나고 평상시에는 사라진다.

제품의 핵심 가치는 다음 세 가지다.

1. 플랫폼의 채팅, 내비게이션, 추천 영역과 플레이어 크롬을 제거한 영상 중심 시청 경험
2. 1개, 2개, 최대 4개 방송을 일관된 자체 플레이어와 단일 오디오 포커스로 시청하는 멀티뷰 경험
3. 플랫폼별 재생 URL, 토큰, CDN 차이를 어댑터로 격리하여 UI와 재생 엔진을 공통으로 유지하는 구조

이 제품은 영상 소스를 재배포하거나 저장하지 않는다. 브라우저가 사용자의 네트워크에서 플랫폼 CDN에 직접 접속하며, 서버가 전달하는 인스트림 콘텐츠를 임의로 탐지하거나 제거하지 않는다.

## 2. 제품 원칙

### 2.1 영상이 인터페이스다

재생 중에는 화면 대부분을 영상이 차지한다. 채널명, 화질, 버튼은 포인터 이동, 키보드 포커스, 오류 발생 때만 노출한다. 장식은 영상 위에 상시 남지 않는다.

### 2.2 한 번에 하나의 소리

멀티뷰에서 여러 방송의 소리를 동시에 재생하지 않는다. 선택된 타일만 오디오 포커스를 가지며 나머지는 음소거된다. 이 정책은 사용자가 방송을 추가하거나 레이아웃을 바꿔도 유지된다.

### 2.3 실패를 숨기지 않고 회복은 자동화한다

일시적인 네트워크 오류와 만료된 세션은 자동으로 복구한다. 원본·고화질 경로가 실패하면 접근 가능한 최고 일반 화질로 폴백하고 이유를 짧게 알린다. 인증, 연령, 구독, 비밀번호, 지역 또는 권리 제한은 우회하지 않고 플랫폼에서 열 수 있는 경로를 제공한다.

### 2.4 권한은 필요할 때만 요청한다

설치 시 권한을 최소화한다. 동적으로 배정된 CDN 접근 권한은 실제로 해당 플랫폼을 처음 재생할 때 설명과 함께 요청한다. 사용자가 거부해도 확장 전체가 멈추지 않고 해당 타일만 권한 필요 상태로 남는다.

### 2.5 조용하고 정교한 시각 언어

UI는 OLED 블랙 기반의 Ethereal Glass 계열을 사용하되, 영상 위에 큰 글래스 패널이나 지속적인 블러를 얹지 않는다. 물리적인 깊이는 런처, 다이얼로그, 컨트롤 아일랜드 같은 제한된 요소에만 이중 베젤 구조로 표현한다.

- 플랫폼 플레이어와 독립적인 HLS 재생

- 타일별 자동 및 명시적 화질 선택

- 타일 단독 전체화면과 플레이어 창 전체화면

- 키보드 전용 조작

### 3.2 명시적 제외 범위

- 플랫폼 채팅, 후원, 구독, 알림, 드롭스

- DRM 또는 지역·권리 제한 우회

- 별도 네이티브 프로그램 설치
- 녹화, 다운로드, 클립 생성, 재송출
- 광고 탐지 또는 광고 세그먼트 제거

- 5개 이상의 동시 스트림
- 모바일 브라우저와 Safari

- 별도 백엔드와 미디어 프록시

## 4. 핵심 사용자 흐름

### 4.1 플랫폼 라이브 페이지에서 시작

1. 사용자가 치지직 또는 SOOP 라이브 페이지에서 확장 아이콘을 누른다.
2. 런처가 현재 탭 URL을 플랫폼과 방송 식별자로 해석한다.
3. 플레이어 창이 없으면 `플레이어에서 열기`, 이미 있으면 `현재 플레이어에 추가`를 기본 행동으로 제시한다.
4. 필요한 플랫폼 API·CDN 권한이 없다면 용도와 대상 도메인을 설명한 후 사용자 동작으로 요청한다.
5. 전용 플레이어 창을 열거나 기존 창에 방송을 추가한다.
6. 첫 프레임은 브라우저 자동재생 정책과 무관하게 항상 음소거 상태로 시작한다. 플레이어 창에서 첫 클릭 또는 Space 입력 시 선택 타일에 오디오 포커스를 주고 소리를 켠다.
7. 원래 플랫폼 탭은 재생과 무관하며 사용자가 직접 닫아도 된다. 확장이 자동으로 탭을 닫지는 않는다.

### 4.2 URL로 방송 추가

1. 비지원 페이지에서 확장 아이콘을 누르거나 플레이어의 추가 버튼을 누른다.
2. URL 입력 필드에 치지직 또는 SOOP 라이브 URL을 붙여넣는다.
3. 입력과 동시에 플랫폼·채널 형식을 로컬에서 검증한다.
4. 유효하면 채널명과 현재 라이브 상태를 조회하고 추가한다.
5. 같은 방송이 이미 있으면 중복 타일을 만들지 않고 기존 타일을 포커스한다.

### 4.3 멀티뷰 구성

1. 두 번째 방송은 자동으로 음소거되어 추가된다.
2. 스트림 수에 따라 자동 레이아웃을 적용한다.
3. 사용자가 타일을 클릭하면 오디오 포커스와 키보드 포커스가 해당 타일로 이동한다.
4. 드래그로 타일 순서를 바꿀 수 있다. 드래그 중 영상 재생은 중단하지 않는다.
5. 세 번째 방송은 2×2 레이아웃의 세 칸을 사용하고 나머지 한 칸은 조용한 추가 슬롯으로 남는다.
6. 네 번째 방송을 추가하면 추가 슬롯이 영상으로 전환된다.
7. 다섯 번째 방송 추가 요청은 기존 타일을 바꾸지 않고 `플레이어가 가득 찼어요 · 방송은 최대 4개까지 재생할 수 있어요`로 안내한다.

### 4.4 다시 실행

플레이어 창을 닫으면 모든 네트워크 요청과 미디어 버퍼를 즉시 정리한다. 다음 실행 때 지난 URL, 순서, 레이아웃만 복원 후보로 보여주며 사용자 승인 없이 자동 재생하거나 네트워크 요청을 시작하지 않는다. 서명 URL, 접근 토큰, 쿠키는 저장하지 않는다.

## 5. 정보 구조와 화면

### 5.1 확장 런처

런처는 360×자동 높이의 작은 팝업이며 최대 높이는 560px이다. 구성은 세 구역이다.

1. 상단 상태 행
   - `Split View` 워드마크
   - 플레이어 실행 상태: `실행 중 · 2개 재생` 또는 표시 없음
2. 현재 페이지 카드
   - 지원 라이브 페이지: 플랫폼, 채널명, 방송 제목, 라이브 상태
   - 비지원 페이지: `현재 페이지에서 방송을 찾지 못했어요`
   - 기본 CTA: `플레이어에서 열기` 또는 `현재 플레이어에 추가`
3. URL 입력
   - 라벨: `다른 방송 추가`
   - 플레이스홀더: `치지직 또는 SOOP 라이브 링크`
   - 붙여넣은 URL이 유효하면 Enter로 실행

지난 구성이 있으면 팝업 하단에 `지난 구성 복원 · 3개 방송`을 보조 행동으로 제공한다. 설정은 우측 상단 아이콘 하나로 진입하며 런처에 상시 옵션 목록을 펼치지 않는다.

### 5.2 플레이어 창

플레이어는 `chrome-extension://` 문서로 구성된 별도 popup 타입 창이다. 최초 크기는 1280×760, 최소 권장 크기는 720×480이며 마지막 창 위치와 크기를 저장한다. OS 창 프레임 외에는 자체 헤더를 상시 표시하지 않는다.

화면 계층은 다음과 같다.

1. 영상 그리드
2. 타일별 상태·컨트롤 오버레이
3. 하단 중앙 글로벌 컨트롤 아일랜드
4. 모달·권한 요청·치명적 오류 레이어

포인터가 1.8초 동안 움직이지 않고 키보드 포커스가 컨트롤에 없으면 모든 비필수 UI가 사라진다. 포인터 이동, Tab, 숫자 키, 미디어 상태 변화가 발생하면 다시 나타난다.

### 5.3 빈 플레이어

스트림이 없을 때 중앙에 큰 대시보드나 설명을 만들지 않는다. 짧은 문장 `방송 링크를 추가해 시작하세요`와 URL 입력 CTA를 한 개의 이중 베젤 패널 안에 배치한다. 하단에는 지원 플랫폼을 텍스트로만 표시하고 공식 로고를 임의 사용하지 않는다.

### 5.4 설정 화면

설정은 별도 전체 페이지가 아니라 플레이어 또는 런처에서 여는 우측 시트다. MVP 설정은 다음으로 제한한다.

- 기본 레이아웃: 자동, 2분할 가로, 2분할 세로
- 스트림 추가 시 동작: 항상 음소거 고정
- 자동 화질: 켜짐 고정, 최대 화질 상한 선택 가능
- 컨트롤 자동 숨김 시간: 1.2초, 1.8초, 3초
- 지난 구성 저장: 기본 켜짐
- 진단 로그 내보내기
- 부여한 선택적 호스트 권한 확인·해제

### 5.5 구조 와이어프레임

런처의 기본 구조는 다음과 같다. 실제 UI는 이 구조를 유지하되 모든 외곽선을 상시 표시하지 않는다.

```text
┌──────────────────────────────────────┐
│ Split View                설정       │
│                                      │
│ ╭──────────────────────────────────╮ │
│ │ LIVE · CHZZK                    │ │
│ │ 침착맨                           │ │
│ │ 오늘의 방송 제목…               │ │
│ │                                  │ │
│ │          플레이어에서 열기   ↗  │ │
│ ╰──────────────────────────────────╯ │
│                                      │
│ 다른 방송 추가                      │
│ ╭──────────────────────────────────╮ │
│ │ 치지직 또는 SOOP 라이브 링크   + │ │
│ ╰──────────────────────────────────╯ │
│                                      │
│ 지난 구성 복원 · 3개 방송           │
└──────────────────────────────────────┘
```

네 개 방송을 재생하는 플레이어의 기본 구조는 다음과 같다.

```text
┌────────────────────────┬────────────────────────┐
│ 침착맨          화질 □ ×│ 우왁굳          화질 □ ×│
│                        │                        │
│        VIDEO 1         │        VIDEO 2         │
│                        │                        │
├────────────────────────┼────────────────────────┤
│ 방송 3          화질 □ ×│ 방송 4          화질 □ ×│
│                        │                        │
│        VIDEO 3         │        VIDEO 4         │
│                        │                        │
│              ╭──────────────────╮               │
│              │ ＋  격자  2/4  ⛶ │               │
│              ╰──────────────────╯               │
└────────────────────────┴────────────────────────┘
```

컨트롤이 숨겨지면 타일 구분용 2px gutter를 제외한 텍스트와 버튼이 모두 사라진다. 오류 또는 권한 요청이 발생한 타일만 상태 패널을 유지한다.

## 6. 레이아웃 규칙

### 6.1 자동 레이아웃

- 스트림 1개: 1×1
- 스트림 2개: 창 가로/세로 비율이 1.2 이상이면 좌우, 미만이면 상하
- 스트림 3개: 2×2에서 마지막 칸을 추가 슬롯으로 유지
- 스트림 4개: 2×2

레이아웃 변경 시 `<video>` 요소를 재생성하지 않고 CSS Grid 위치만 바꾼다. 버퍼와 재생 위치가 유지되어야 한다.

### 6.2 영상 맞춤

기본은 `object-fit: contain`이며 영상을 자르지 않는다. 남는 영역은 순수 블랙으로 처리한다. `채우기` 크롭 모드는 MVP에서 제공하지 않는다. 타일 간 간격은 2px이고 포커스 타일은 영상 영역을 침범하지 않는 안쪽 광선으로만 구분한다.

### 6.3 전체화면

- 타일 더블클릭 또는 `F`: 선택 타일 단독 전체화면
- `Shift+F`: 플레이어 창 전체화면
- `Esc`: 타일 전체화면, 모달, 창 전체화면 순서로 가장 안쪽 상태부터 해제

## 7. 타일 인터랙션

### 7.1 상단 오버레이

포인터 활성 상태에서 좌측 상단에 채널명과 플랫폼 텍스트를 표시한다. 우측 상단에는 다음 순서의 아이콘을 둔다.

- 화질
- 타일 전체화면
- 타일 닫기

방송 제목은 한 줄 말줄임으로 채널명 아래에 표시하며, 영상의 중요한 중앙 영역을 가리지 않도록 최대 너비를 타일의 60%로 제한한다.

### 7.2 하단 오버레이

- 재생·일시정지
- 음소거·음량
- 현재 화질: `자동 · 720p` 형식
- 라이브 지연 상태는 정확한 값을 계산할 수 있을 때만 `LIVE - 6s`로 표시

개인 라이브는 탐색 가능한 전체 타임라인을 제공하지 않는다. HLS가 라이브 시프트 범위를 제공하더라도 MVP에서는 라이브 엣지 복귀 버튼만 제공한다.

### 7.3 오디오 포커스

- 클릭 또는 숫자 키 1–4로 타일을 선택한다.
- 선택한 타일은 이전 음량으로 복원되고 기존 오디오 타일은 음소거된다.
- 선택된 타일을 다시 클릭해도 재생·일시정지는 바꾸지 않는다.
- `M`은 선택 타일의 음소거만 토글한다.
- 새 스트림은 항상 음소거 상태로 시작한다.
- 동시에 두 개 이상의 타일을 유음으로 만드는 기능은 제공하지 않는다.

### 7.4 글로벌 컨트롤 아일랜드

하단 중앙에 떠 있는 작은 pill 형태이며 다음 기능만 담는다.

- 방송 추가
- 레이아웃 변경
- 선택 타일 표시 `2 / 4`
- 창 전체화면
- 설정

각 아이콘은 40×40px 이상의 클릭 영역을 갖고, 라벨은 툴팁과 스크린리더 이름으로 제공한다. 컨트롤은 화면 하단에서 20px 떨어져 떠 있으며 영상과의 대비가 부족할 때만 국소적인 backdrop blur를 사용한다.

## 8. 시각 디자인 시스템

### 8.1 방향

선택한 시각 언어는 `Ethereal Glass + Z축 아일랜드`다. 영상 그리드는 완전히 평평하고 검게 유지하고, 런처·모달·글로벌 컨트롤에만 정밀 가공된 하드웨어 같은 이중 베젤을 적용한다. 장식보다 영상 몰입을 우선한다.

### 8.2 컬러

- Canvas: `#050505`
- Video gutter: `#000000`
- Raised shell: `rgba(255,255,255,0.055)`
- Inner core: `rgba(14,14,17,0.92)`
- Primary text: `#F4F4F3`
- Secondary text: `#9B9BA1`
- Accent iris: `#9487FF`
- Live: `#FF5B61`
- Success: `#6FDCB3`
- Warning: `#F2BD68`
- Error: `#FF737A`
- Hairline: `rgba(255,255,255,0.09)`

플랫폼별 브랜드 컬러로 타일을 칠하지 않는다. 플랫폼은 작은 텍스트 라벨로만 구분하며 제품 전체는 중립적인 색 체계를 유지한다.

### 8.3 타이포그래피

- 기본 서체: 확장에 포함한 `Geist Variable`
- 숫자·상태: Geist의 tabular numerals 사용
- 런처 제목: 20/26, 600
- 타일 채널명: 14/20, 560
- 본문: 13/19, 450
- 보조 상태: 11/16, 500, 자간 0.02em
- 툴팁: 11/14, 500

원격 폰트를 사용하지 않는다. 글자 굵기는 세 단계 이내로 제한해 영상 위 정보 밀도를 낮춘다.

### 8.4 형태와 간격

- 기본 간격 단위: 4px
- 런처 외곽 패딩: 16px
- 타일 오버레이 안전 여백: 14px
- 글로벌 아일랜드 외곽 반경: 28px
- 모달 외곽 반경: 28px, 내부 반경: 22px
- 버튼 높이: 기본 40px, 주요 CTA 46px
- 타일 간격: 2px

주요 CTA는 pill 형태이며 텍스트와 아이콘을 함께 사용할 때 아이콘은 별도의 28px 원형 내부 아일랜드에 둔다. 일반 기능 버튼에 이 패턴을 남발하지 않는다.

### 8.5 깊이

런처의 현재 페이지 카드, URL 입력 패널, 모달, 글로벌 컨트롤은 다음 이중 베젤 구조를 공유한다.

- Outer shell: 반투명 백색 5.5%, 1px 미만으로 보이는 hairline, 6px 내부 패딩
- Inner core: `#0E0E11` 92%, 위쪽 1px 내부 하이라이트
- 그림자: 검은 단일 그림자가 아니라 넓고 약한 ambient shadow와 짧은 접촉 그림자를 조합

영상 타일에는 카드 그림자나 둥근 모서리를 적용하지 않는다. 영상 자체를 카드처럼 장식하지 않는 것이 원칙이다.

### 8.6 모션

- 표준 진입: 260ms, `cubic-bezier(0.32, 0.72, 0, 1)`
- 컨트롤 숨김: 180ms opacity와 4px translate
- 모달 진입: 320ms opacity, scale 0.985→1, translateY 8px→0
- 타일 재배치: 420ms transform 기반 spring-like curve
- 버튼 누름: scale 0.98, 100ms
- 오류 복구 스피너: 회전 대신 세 점의 순차 opacity 사용

`top`, `left`, `width`, `height`는 애니메이션하지 않는다. `prefers-reduced-motion`에서는 이동과 scale을 제거하고 100ms 이내의 opacity 전환만 사용한다. 영상 재생 중 대형 blur와 지속적인 그레인 효과를 사용하지 않는다.

## 9. 접근성과 키보드

목표는 WCAG 2.2 AA다.

- 모든 아이콘 버튼에 명시적 접근성 이름 제공
- 키보드 포커스는 2px accent ring과 2px offset으로 표시
- 포커스, 오류, 음소거 상태를 색상만으로 전달하지 않음
- 텍스트 대비 4.5:1 이상, 큰 텍스트 3:1 이상
- 클릭 대상 최소 40×40px
- HLS에 자막 트랙이 존재하면 브라우저 텍스트 트랙으로 노출
- 토스트는 `aria-live="polite"`, 재생 불가 오류는 `assertive`
- 드래그 정렬은 키보드의 `[`와 `]`로도 수행 가능

키보드 계약은 다음과 같다.

| 키 | 동작 |
|---|---|
| `1`–`4` | 해당 타일 선택 및 오디오 포커스 이동 |
| `Space` | 선택 타일 재생·일시정지 |
| `M` | 선택 타일 음소거 |
| `F` | 선택 타일 전체화면 |
| `Shift+F` | 플레이어 창 전체화면 |
| `L` | 다음 레이아웃 |
| `A` 또는 `+` | 방송 추가 다이얼로그 |
| `[` / `]` | 선택 타일 순서 이동 |
| `Esc` | 현재 최상위 오버레이 또는 전체화면 해제 |

입력 필드에 포커스가 있을 때는 `Esc`와 Enter를 제외한 전역 단축키를 처리하지 않는다.

## 10. 아키텍처

### 10.1 구성 요소

#### Manifest V3 확장 셸

- 확장 action과 런처 팝업
- 플레이어 창 생성·재사용
- 최소 권한과 선택적 호스트 권한 선언
- 패키지 내부에 HLS.js, 폰트, 아이콘 포함
- 원격 코드 실행 없음

#### Service Worker

- 플레이어 창 레지스트리
- 현재 탭과 런처 간 메시지 중계
- 플랫폼 어댑터의 세션 해석 요청 조정
- 설정과 복원 가능한 워크스페이스 메타데이터 저장
- 선택적 호스트 권한 요청 준비
- 필요할 경우 플레이어 창에만 한정된 세션 DNR 규칙 생성·제거

서비스 워커는 미디어 세그먼트를 프록시하거나 장시간 연결을 소유하지 않는다. 종료와 재시작을 전제로 모든 필수 상태를 저장소 또는 플레이어 문서에 둔다.

#### Player Document

- 지속적인 UI 상태의 단일 소유자
- 타일과 `<video>` 생명주기 관리
- HLS.js 인스턴스 관리
- 레이아웃, 오디오 포커스, 단축키, 전체화면 관리
- 재시도와 사용자 상태 표시

#### Platform Adapters

- URL 식별과 정규화
- 방송 메타데이터 조회
- 재생 세션 생성과 갱신
- 플랫폼별 HLS URL 재작성
- 제한 상태를 공통 오류 코드로 변환

#### Playback Engine

- HLS.js를 감싼 공통 엔진
- manifest, variant, segment 요청 훅
- 자동 화질과 최대 화질 상한
- live edge 추적
- fatal/non-fatal 오류 분류
- 재생 통계와 로컬 진단 이벤트

### 10.2 데이터 흐름

```text
라이브 URL
  → URL 검증·정규화
  → 플랫폼 어댑터
  → 임시 PlaybackSession
  → HLS 요청 훅·URL 재작성
  → HLS.js / MediaSource
  → 브라우저 <video>
```

플랫폼 콘텐츠 스크립트는 현재 URL이나 페이지 식별이 URL만으로 불가능한 경우에 한해 사용한다. 콘텐츠 스크립트에 서명 URL, 쿠키, AID 등의 민감한 재생 정보를 보내지 않는다.

## 11. 플랫폼 어댑터 계약

각 어댑터는 다음 의미 계약을 구현한다. 구체적인 API 엔드포인트와 파라미터는 구현 내부에 격리한다.

```ts
interface PlatformAdapter {
  platform: "chzzk" | "soop";
  match(inputUrl: string): boolean;
  normalize(inputUrl: string): Promise<StreamSource>;
  resolveMetadata(source: StreamSource): Promise<StreamMetadata>;
  createSession(source: StreamSource): Promise<PlaybackSession>;
  refreshSession(source: StreamSource, previous: PlaybackSession): Promise<PlaybackSession>;
}
```

### 11.1 치지직 어댑터

- 채널 ID 기반 URL 정규화
- live detail 응답에서 공개 라이브 상태와 HLS media 선택
- HLS master URL의 서명과 만료 처리
- 필요한 경우 `hdnts` 값을 미디어 세그먼트의 `__bgda__`로 전달하는 URL 재작성
- 타임머신 전용 응답이 오더라도 MVP 재생 가능한 live edge만 사용
- 성인 또는 playback media 비공개 응답은 `restricted` 또는 `login_required`로 변환

### 11.2 SOOP 어댑터

- BJ ID와 방송 번호 정규화
- 채널 조회에서 방송 번호, CDN 관리자, 제공 화질 추출
- 방송과 화질별 AID 세션 획득
- CDN 할당 응답에서 HLS URL 선택
- HLS 요청에 AID와 필요한 플랫폼 요청 컨텍스트 적용
- CDN별 실패 시 허용된 CDN 후보 순회
- 비밀번호, 구독, 로그인 필요 상태를 공통 제한 오류로 변환
- 고화질·P2P 강제 응답 시 일반 화질 세션으로 폴백

## 12. 데이터 모델

### 12.1 영구 저장 가능 모델

```ts
type Platform = "chzzk" | "soop";

interface StreamSource {
  id: string;
  platform: Platform;
  originalUrl: string;
  canonicalUrl: string;
  channelKey: string;

interface StreamPreference {
  sourceId: string;
  volume: number;

}

  version: 1;
  sources: StreamSource[];
  order: string[];
  layout: "auto" | "single" | "two-horizontal" | "two-vertical" | "grid";
```

### 12.2 메모리 전용 모델

```ts
interface PlaybackSession {
  sourceId: string;
  manifestUrl: string;
  expiresAt?: number;
  requestContext?: Record<string, string>;
  urlRewriteMode?: "none" | "chzzk-bgda" | "soop-aid";
```

`PlaybackSession`, manifest URL, AID, 서명 쿼리, 요청 헤더는 `chrome.storage`, LocalStorage, 로그, 동기화 저장소에 기록하지 않는다. 진단 내보내기에서는 URL의 전체 쿼리 문자열을 제거한다.

## 13. 권한과 보안

### 13.1 권한 원칙

- `activeTab`: 사용자가 런처를 연 현재 탭의 URL 감지
- `storage`: 설정과 비민감 워크스페이스 스냅샷
- 플랫폼 API의 좁은 `host_permissions`
- 동적 CDN을 위한 `optional_host_permissions`
- SOOP 요청 컨텍스트 보정이 실제로 필요한 경우에만 `declarativeNetRequestWithHostAccess`
- MVP에서는 `cookies`, `tabs`, `<all_urls>`, `nativeMessaging`을 요청하지 않음

### 13.2 네트워크 제한

- 사용자가 보낸 URL을 임의 fetch URL로 직접 사용하지 않는다.
- 각 플랫폼 어댑터가 허용한 HTTPS 호스트와 경로 형식만 요청한다.
- redirect 후 최종 URL도 플랫폼별 CDN 허용 규칙으로 다시 검증한다.
- `http://`, localhost, 사설 IP, file URL은 미디어 소스로 허용하지 않는다.
- 콘텐츠 스크립트 발신 메시지는 sender와 payload schema를 검증한다.
- DOM 삽입은 `textContent`와 안전한 속성 API만 사용한다.
- 세션 DNR 규칙은 플레이어 요청과 대상 CDN에만 한정하고 플레이어 종료 시 제거한다.

### 13.3 개인정보

외부 분석 서버를 사용하지 않는다. 확장은 검색 기록, 전체 방문 기록, 채팅, 계정 식별자, 쿠키를 수집하지 않는다. 로컬 진단 로그는 최근 200개 이벤트를 순환 보관하고 24시간이 지나면 삭제한다.

## 14. 오류 처리 정책

오류는 복구 가능, 사용자 조치 필요, 지원 불가의 세 계층으로 처리한다.

| 코드 | 정책 | 사용자 메시지 |
|---|---|---|
| `network_lost` | 0, 1, 2, 5초 후 재시도, 이후 수동 버튼 | 연결을 다시 잡고 있어요 |
| `session_expired` | 어댑터로 1회 즉시 갱신 | 표시하지 않음, 실패 시만 노출 |
| `quality_unavailable` | 다음 접근 가능 화질로 폴백 | 일반 화질로 전환했어요 |
| `permission_required` | 타일 유지, 사용자 버튼으로 권한 요청 | 이 방송의 CDN 접근 권한이 필요해요 |
| `permission_denied` | 자동 재요청 금지 | 권한을 허용하면 재생할 수 있어요 |
| `offline` | 타일 유지, 수동 새로고침 | 지금은 방송 중이 아니에요 |
| `live_ended` | 요청 중단, 타일 종료 상태 | 방송이 종료됐어요 |
| `login_required` | 우회하지 않음 | 플랫폼 로그인이 필요한 방송이에요 |
| `restricted` | 우회하지 않음 | 이 방송은 Split View에서 재생할 수 없어요 |
| `password_required` | 비밀번호 입력을 받지 않음 | 비밀번호 방송은 아직 지원하지 않아요 |
| `adapter_contract_changed` | 진단 ID 제공 | 플랫폼 변경으로 재생 정보를 읽지 못했어요 |
| `playback_fatal` | 세션 1회 재생성 후 정지 | 재생을 시작하지 못했어요 |

오류 카드에는 최대 두 개의 행동만 둔다.

- 기본: `다시 시도`
- 보조: `플랫폼에서 열기`

권한 오류일 때만 기본 행동을 `접근 허용`으로 바꾼다. 오류 상세와 진단 ID는 펼침 영역에 두고 기본 화면에 스택 트레이스나 HTTP 상태 전문을 노출하지 않는다.

## 15. 로딩과 상태 UX

- 메타데이터 조회 중: 썸네일이 있으면 저채도 배경으로 사용하고 중앙에 세 점 pulse
- manifest 준비 중: `스트림 연결 중`
- 첫 프레임 대기: 영상 영역은 검게 유지하고 3초가 지나야 텍스트 표시
- 자동 재연결: 기존 마지막 프레임을 흐리게 하지 않고 그대로 유지하며 작은 상태 pill만 표시
- 화질 폴백: 4초 토스트 후 사라짐, 화질 메뉴에는 실제 재생 화질 유지
- 라이브 복귀: 지연이 충분히 커졌을 때만 `라이브로` 버튼 노출
- 성공 토스트는 방송 추가, 레이아웃 변경처럼 화면에서 이미 결과가 명확한 동작에는 사용하지 않음

## 16. 성능 정책

- 스트림마다 HLS.js 인스턴스 하나와 `<video>` 하나를 유지
- 숨겨진 플랫폼 iframe이나 플레이어를 백그라운드에 유지하지 않음
- UI 렌더링과 세그먼트 요청을 서비스 워커에 프록시하지 않음
- 타일이 보이는 동안 모든 스트림의 영상은 재생하고 비포커스 타일은 음소거
- 백그라운드로 완전히 가려진 플레이어 창의 처리 정책은 브라우저 기본 절전 정책을 따르며 이를 우회하지 않음
- 레이아웃 모션은 transform과 opacity만 사용
- 대형 backdrop blur, canvas 영상 복사, CSS 필터 기반 영상 효과 사용 금지
- 세 개 이상 재생할 때 비포커스 타일의 자동 화질 상한은 기본 720p, 포커스 타일은 사용자 상한까지 허용
- `getVideoPlaybackQuality()`에서 15초 구간의 dropped frame 비율이 10%를 넘는 타일은 자동 화질을 한 단계 낮추고 30초 안정 후에만 승격 후보로 삼음

## 17. 테스트 전략

### 17.1 단위 테스트

- 플랫폼별 URL 인식, canonical URL, 채널·방송 ID 추출
- 허용 호스트와 redirect 검증
- 치지직 playback JSON 파싱과 세그먼트 URL 재작성
- SOOP 방송 조회, AID, CDN 할당 응답 파싱
- 화질 정렬과 폴백 선택
- 오류 응답의 공통 오류 코드 변환
- 워크스페이스 직렬화에서 세션·토큰이 제거되는지 검증
- 오디오 포커스 불변식: 유음 타일이 최대 하나인지 검증
- 스트림 수와 창 비율에 따른 자동 레이아웃

플랫폼 응답 fixture는 실제 토큰, 사용자 ID, 전체 서명 URL을 제거한 형태로 저장한다.

### 17.2 재생 엔진 통합 테스트

- 로컬 테스트 HLS 서버의 master/variant/segment 재생
- manifest와 세그먼트의 상대·절대 URL 처리
- 세션 만료를 모사한 403 후 세션 갱신
- variant 실패 후 한 단계 화질 폴백
- 일시 네트워크 단절 후 live edge 복귀
- HLS.js fatal 오류에서 인스턴스 정리와 재생성
- 플레이어 종료 후 열린 요청과 MediaSource가 남지 않는지 검증

### 17.3 UI 자동화 테스트

- 지원 페이지와 비지원 페이지의 런처 상태
- URL 붙여넣기, 중복 추가, 최대 4개 제한
- 1·2·3·4개 레이아웃 전환
- 드래그 및 키보드 재정렬
- 오디오 포커스 이동
- 컨트롤 자동 숨김과 키보드 재노출
- 타일·창 전체화면 진입과 Esc 순서
- 권한 요청, 거부, 재시도
- 오류 카드와 플랫폼 열기
- reduced motion과 키보드 포커스

### 17.4 실플랫폼 스모크 테스트

릴리스 전 각 플랫폼에서 다음 매트릭스를 수동 검증한다.

- 공개 일반 방송 5개 이상
- 서로 다른 CDN이 배정되는 방송
- 30분 연속 재생
- 방송 중 화질 변경
- 2개와 4개 동시 재생
- 방송 종료 전환
- 로그아웃 상태
- 고화질 실패 후 일반 화질 폴백
- 확장 재시작 후 지난 구성 복원

실플랫폼 테스트는 녹화하지 않고 네트워크 응답 fixture를 생성할 때 모든 서명·쿠키·계정 데이터를 제거한다.

## 18. 완료 기준

MVP는 다음 조건을 모두 충족할 때 완료로 본다.

1. 지원되는 라이브 페이지와 직접 입력 URL에서 치지직·SOOP 공개 방송을 확장 플레이어로 열 수 있다.
2. 원래 플랫폼 탭을 닫은 뒤에도 자체 HLS 플레이어가 재생을 유지한다.
3. 한 창에서 최대 네 방송을 1·2·4분할 규칙으로 재생하며 레이아웃 변경이 재버퍼링을 유발하지 않는다.
4. 동시에 소리가 나는 타일은 최대 하나이며 클릭과 숫자 키로 오디오 포커스를 전환할 수 있다.
5. 접근 가능한 화질 중 최적 화질을 선택하고 고화질 경로 실패 시 일반 화질로 자동 전환한다.
6. 만료된 재생 세션을 자동 갱신하며 일시 네트워크 단절 후 사용자 새로고침 없이 복구한다.
7. 지원하지 않는 인증·권리 제한 방송을 우회하지 않고 이해 가능한 상태와 플랫폼 열기 행동을 제공한다.
8. 저장소와 진단 로그 어디에도 manifest 서명, AID, 쿠키 또는 전체 민감 URL이 남지 않는다.
9. 설치 시 전체 사이트 접근, 쿠키, 네이티브 메시징 권한을 요구하지 않는다.
10. 런처와 플레이어의 모든 핵심 동작을 마우스 없이 수행할 수 있다.
11. 네 개 스트림을 30분 재생한 스모크 테스트에서 플레이어 충돌, 지속적인 메모리 증가, 중복 오디오가 발생하지 않는다.
12. 녹화·다운로드·재송출·광고 필터링 코드가 포함되지 않는다.

## 19. 주요 위험과 대응

### 비공개 API 변경

가장 큰 제품 위험이다. 플랫폼별 응답 파싱과 URL 재작성은 어댑터 내부로 격리하고, fixture 기반 계약 테스트가 실패하면 UI 변경 없이 해당 어댑터만 수정할 수 있어야 한다. `adapter_contract_changed` 오류는 일반 네트워크 오류와 구분한다.

### 그리드·P2P 기반 고화질 강제

순수 브라우저 확장으로 우회하거나 재구현하지 않는다. HLS로 접근 가능한 최고 화질을 사용하고 실패 시 일반 화질로 폴백한다. 최고 화질 보장은 제품 메시지와 완료 기준에 포함하지 않는다.

### 광범위한 CDN 권한

전체 HTTPS 권한을 설치 시 요청하지 않는다. 런타임에 실제로 배정된 CDN origin만 요청하고 설정에서 사용자가 해제할 수 있게 한다. 새로운 CDN은 허용 목록과 테스트를 추가한 확장 업데이트를 통해 지원한다.

### 스토어와 플랫폼 정책

제품 설명은 영상 집중 및 멀티뷰 재생으로 한정한다. 다운로드, 광고 차단, 접근 제한 우회를 암시하지 않는다. 공개 배포 전 최신 플랫폼 약관과 Chrome Web Store 정책을 별도로 검토한다.

### 네 개 스트림의 자원 사용량

자동 화질 상한과 성능 진단을 제공한다. 세 개 이상에서는 비포커스 타일을 기본 720p로 제한하고, 15초 구간의 dropped frame 비율이 10%를 넘으면 해당 타일 화질을 한 단계 낮춘다. 영상 프레임을 canvas로 복제하지 않으며 브라우저의 하드웨어 디코딩 경로를 유지한다.
